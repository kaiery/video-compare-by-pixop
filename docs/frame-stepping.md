# 双向逐帧浏览

本分支本体版本标识：`20260920-frame-step-cache`。GUI 仍通过选择外部 `video-compare.exe` 使用它；更新启动器不会替换用户已选中的旧引擎。

## 操作与时间轴

- `A`、`Shift+A`：暂停并显示前一个参考帧。
- `D`、`Shift+D`：暂停并显示后一个参考帧。
- `Space`：从当前显示位置恢复播放。
- `,`、`.`：保留原有缓冲区往返／正向循环功能。

以左侧参考视频经解码和滤镜处理后的帧序列为准，包括交换显示左右后。右侧选择覆盖参考时间的帧，应用各自的时间变换；不同帧率的视频不保证同时各走一个源帧。左侧为静态图片时，没有可步进的参考帧序列。

可变帧率的原始时间戳核验需启用已有解码选项 `trust_dec_pts=1`，例如 `--left-decoder-options trust_dec_pts=1`。未启用时沿用本体现有时间戳推算逻辑。改变帧率或时间戳的滤镜会改变可浏览的参考序列。

## 实现

原 `A/D` 仅改变缓存下标，碰到边界就停止；原 `Shift+A` 按平均帧时长做时间寻址，无法准确找到前一帧。

现在缓存内直接浏览已验证相邻的帧组合。正常播放记录实际参考帧的相邻关系，包括被同步流程丢弃的帧；只有相邻关系与右侧时间对齐都满足要求时，才直接使用播放缓存，避免把缓存中的跳帧当成逐帧。

缓存外仍进行两阶段重新解码，但后退会一次补齐最多 `frame-buffer-size` 个参考位置：先向前定位关键帧并收集真实呈现时间戳，再顺序解码并对齐这一批位置的全部输入。随后在这一批缓存内退帧无需重复寻址。后退定位区间不足时逐步向前扩展。扫描每轮有固定消费上限，期间保留当前画面并继续处理窗口事件。

缓存像素采用引用计数，同一右侧画面对应多个参考时间时共享像素。补齐前释放旧历史，仅保留当前显示帧，避免同时持有两批完整历史。缓存容量仍受用户配置限制；设为 1 无法获得批量缓存收益。首尾探测不会丢弃等待中的反向按键；从普通播放进入末帧手动浏览时，必要时重新对齐不同帧率的右侧输入。

完成后更新各侧缓存。恢复播放时重新对齐当前显示位置，并保留下一帧预读，避免从旧解码位置跳走。首尾边界保持画面；寻址失败保留当前画面并显示提示。长 GOP、复杂滤镜或高分辨率输入可能需要较长的重新解码时间；非可寻址输入不保证向后逐帧。

## 自动复验

在可构建本体的环境中执行：

```sh
make check-one TEST=frame_step
make frame-step-check
# 可选：增加 720p 左右画面逐帧 PNG 核对
FRAME_STEP_HD=1 make frame-step-check
```

第二项需要 `ffmpeg`、`ffprobe` 和 Bash。脚本生成 H.264 长 GOP / B 帧及可变帧率测试素材，在临时目录使用 SDL dummy/software 驱动运行，退出后删除素材和 PNG。仅向本进程 SDL 队列投递事件，不注入系统键鼠；dummy 驱动下的时间戳复制也不使用桌面剪贴板。

每个参考帧与 ffprobe 输出的时间戳核对，反向和正向遍历保存左右 PNG 并逐字节比较。以下为本次实机运行的验收范围：

| 项目 | 状态 | 用例 |
| --- | --- | --- |
| 实际时间戳选帧与队列 EOF 状态 | 已验收 | 非均匀间隔、首尾、微秒级间隔及排空／重启 |
| 默认缓存连续退帧 | 已验收 | 75 帧，缓存 50，74 次后退仅 2 次寻址；逐帧时间戳和左右 PNG 一致 |
| 720p 默认缓存退帧 | 已验收 | 75 帧，缓存 50，EOF→第一帧→EOF；全部左右 PNG 一致，74 次后退仅 2 次寻址 |
| 越过缓存边界持续后退 | 已验收 | 75 帧，缓存 3，EOF→第一帧→EOF |
| 最小缓存与同源输入 | 已验收 | 75 帧，缓存 1，左右使用同一个文件 |
| 可变帧率及多右侧 | 已验收 | 50 个非均匀参考帧、两个 30 fps 右侧，参考启用 `trust_dec_pts=1` |
| 按键别名、边界和恢复播放 | 已验收 | 交替 A/Shift+A、D/Shift+D，首尾额外按键，退帧后 Space 及右侧切换 |
| 共用播放与寻址流程回归 | 已验收 | baseline、event-injection、seek、still-seek、frame-navigation、buffer-forward-only、buffer-pingpong、sync-mismatch、multi-right-sync、crop-copy 共十组 |
| 非可寻址网络流、全部硬件及复杂时序滤镜组合 | 未完成 | 不将上述文件测试扩大为全部输入组合通过 |

复验程序为 `tests/integration_frame_step.cpp`。开发过程产物放在被 Git 忽略的 `.local-build/`，不覆盖用户原来的引擎目录。

## 退帧性能记录（2026-09-19）

下表为本机 SDL dummy/software 驱动、相同构建优化级别下的按键投递到读取目标参考时间的测量。它包含测试轮询开销，不是屏幕显示延迟；每个用例从 EOF 连续后退 74 帧，缓存为默认 50。PNG 保存时间不计入按键延迟。小尺寸片段同时通过左右 PNG 逐帧核对。

| 输入与版本 | 后退寻址次数 | 首次后退 | 平均后退 | P95 | 最慢一次 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 160×96、25 fps、H.264 GOP 50 / B 帧，优化前 | 148 | 77.2 ms | 70.3 ms | 78.4 ms | 81.9 ms |
| 同规格，优化后 | 2 | 2.5 ms | 3.7 ms | 3.6 ms | 72.6 ms |
| 1280×720、25 fps、H.264 GOP 50 / B 帧，优化后（时间戳测量，关闭 PNG） | 2 | 4.0 ms | 9.2 ms | 3.9 ms | 448.4 ms |

720p 结果说明：缓存内多数按键响应快，但耗尽缓存后的批量重新解码仍有停顿，不能据平均值声称每次按键都立即完成。更高分辨率、长 GOP、多输入和复杂滤镜需要分别实测。720p 旧版测试遇到 EOF 寻址过程中反向按键被清空的问题，未完成遍历，因此没有给出旧版高清平均值。

测试工具支持 `FRAME_STEP_SKIP_PNG=1` 单独测时间戳与延迟；默认执行 PNG 核对。`FRAME_STEP_MAX_REVERSE_SEEKS` 设置寻址次数上限，常规脚本对默认缓存强制校验上限 2。`VIDEO_COMPARE_LOG_FRAME_STEP=1` 可为引擎启用寻址和导航空闲诊断，默认不输出。
